# JIG 설계 자동화 — 참조 구현

제품도면(DXF)과 설계표준 시트(Excel)를 넣으면 **지그 기본도면(DXF)** 을 생성합니다.
생성된 도면은 AutoCAD 등 CAD 프로그램에서 열어 **수정·승인**하는 것을 전제로 합니다.

---

## ⚠️ 먼저 읽어주십시오

### 이것은 완성된 시스템이 아닙니다

**뼈대(참조 구현)입니다.** 배치 규칙이 비어 있기 때문입니다.

| | |
|---|---|
| 지금 들어있는 설계표준 값 | **전부 가짜(더미)입니다** |
| 지금 생성되는 지그 형상 | **공학적 의미가 없습니다** |
| 담당자가 해야 할 일 | **설계표준 시트를 실제 값으로 채우는 것** |

시트를 채우기 전까지 결과물은 "프로그램이 돌아간다"는 것만 보여줍니다.
**설계표준이 이 시스템의 전부이고, 나머지는 그것을 적용하는 껍데기입니다.**

### 🔒 보안

- **저장소는 반드시 Private 으로 유지하십시오.**
- **고객 도면·품번을 커밋하지 마십시오.** `.gitignore` 가 도면 확장자를 막아두었지만,
  최종 책임은 커밋하는 사람에게 있습니다.
- 한 번 공개 저장소에 올라간 파일은 삭제해도 복구될 수 있습니다.

## 1. 설치 (최초 1회)

### 1-1. Python 설치
[python.org](https://www.python.org/downloads/) 에서 Python 3.10 이상을 받아 설치합니다.
설치 화면에서 **"Add Python to PATH"** 를 반드시 체크하십시오.

### 1-2. 나머지 설치

**`설치하기.bat` 을 더블클릭하십시오.** 필요한 라이브러리를 받고 확인 테스트까지 실행합니다.
마지막에 `N/N 통과` 가 두 번 나오면 정상입니다.

<details>
<summary>명령 프롬프트로 하려면</summary>

```bash
pip install -r requirements.txt
python test_dxf_layer_classifier.py
python test_rules_and_layout.py
```
</details>

## 2. 사용법 — 세 가지 중 하나를 고르십시오

| 방법 | 실행 | 언제 |
|---|---|---|
| **웹 화면** | `웹서버_실행.bat` | 미리보기를 크게 보고 싶을 때, 여러 명이 쓸 때 → [배포.md](배포.md) |
| **화면 프로그램** | `지그도면_만들기.bat` | 혼자 간단히 쓸 때. 서버 불필요 |
| **명령 프롬프트** | `python layout_engine.py ...` | 여러 도면을 한꺼번에 처리할 때 |

**세 방법 모두 같은 엔진을 호출하므로 결과는 동일합니다.**

## 2-0. 웹 화면으로 하기

**`웹서버_실행.bat` 을 더블클릭하면 브라우저가 열립니다.**

1. 제품도면(.dxf)과 설계표준 시트(.xlsx)를 고릅니다
2. `[지그 도면 만들기]` 를 누릅니다
3. 결과 화면에서 미리보기를 확인하고 파일을 내려받습니다

결과 화면은 **반드시 봐야 할 것부터 위에 놓습니다** — 살두께 위반(빨강) → 확인사항(노랑)
→ 미리보기 → 분류 결과 → 내려받기.

> 기본값은 **이 PC 안에서만** 접속됩니다. 도면이 외부로 나가지 않습니다.
> 사내 다른 PC 에서 접속하게 하려면 **반드시 [배포.md](배포.md) 를 먼저 읽으십시오**
> — 현재 인증 기능이 없습니다.

---

## 2-1. 화면 프로그램으로 하기

**`지그도면_만들기.bat` 을 더블클릭하면 창이 뜹니다.**

```
┌─────────────────────────────────────────────┐
│ 제품도면 (.dxf)      [...............] [찾아보기] │
│ 설계표준 시트 (.xlsx) [...............] [찾아보기] │
│ 지그 타입            [SMT 수대      ]           │
│                                               │
│ [지그 도면 만들기] [시트 새로 만들기] [시트 검사]  │
│                              [결과 폴더 열기]   │
├─────────────────────────────────────────────┤
│ 진행 내용                                      │
│ ── 1단계 · 제품도면 레이어 정리 ──────────      │
│   자동 분류율 91.4%  (확인 필요 5개)            │
│ ── 2단계 · 지그 기본도면 생성 ────────────      │
│   지그 판 178.0 x 98.0 mm  (배열 2x2)          │
└─────────────────────────────────────────────┘
```

**처음이라면 순서가 이렇습니다.**

1. `[설계표준 시트 새로 만들기]` → 저장 위치 지정
2. 만들어진 엑셀을 열어 **노란 칸을 실제 설계표준으로** 바꾸고 저장
   → [설계표준_작성가이드.md](설계표준_작성가이드.md)
3. `[설계표준 시트 검사]` 로 잘못 적은 곳이 없는지 확인
4. 제품도면을 고르고 `[지그 도면 만들기]`
5. `[결과 폴더 열기]` → `..._jig.dxf` 를 CAD 로 열어 수정·승인

> 서버나 인터넷 연결이 필요 없습니다. 이 PC 안에서만 동작합니다.

---

## 2-2. 명령 프롬프트로 하기

화면 대신 명령으로 쓰거나, 여러 도면을 한꺼번에 처리할 때 씁니다.

### ① 설계표준 시트 만들기 (최초 1회)

```bash
python make_rule_sheet.py --jig-type "SMT 수대"
```

`설계표준시트.xlsx` 가 만들어집니다. **엑셀로 열어 노란 칸(값)을 실제 설계표준으로 바꾸십시오.**
자세한 내용은 [설계표준_작성가이드.md](설계표준_작성가이드.md) 를 보십시오.

채운 뒤 검사:

```bash
python rules_loader.py 설계표준시트.xlsx
```

잘못된 곳이 있으면 **몇 행의 무엇이 왜 틀렸는지** 알려줍니다.

### ② 제품도면 레이어 정리

고객 제품도면은 레이어 구분 없이(전부 0번) 오는 경우가 많습니다. 먼저 표준 레이어로 정리합니다.

```bash
python dxf_layer_classifier.py 제품도면.dxf --png
```

| 생성 파일 | 내용 |
|---|---|
| `제품도면_layered.dxf` | 레이어가 정리된 도면 |
| `제품도면_report.csv` | 엔티티별 분류 결과와 판정 근거 (엑셀로 열림) |
| `제품도면_preview.png` | 레이어 색상 미리보기 |

> **`JIG_99_REVIEW` 레이어를 반드시 확인하십시오.** 프로그램이 판단하지 못한 형상입니다.
> 여기 남아 있는 것을 정리하지 않으면 다음 단계에서 홀이 누락될 수 있습니다.

### ③ 지그 기본도면 생성

```bash
python layout_engine.py 제품도면_layered.dxf 설계표준시트.xlsx --jig-type "SMT 수대" --png
```

`제품도면_layered_jig.dxf` 가 생성됩니다. **CAD 로 열어 수정·승인하십시오.**

## 3. 생성된 지그 도면의 레이어

| 레이어 | 내용 |
|---|---|
| `JIGOUT_01_PLATE` | 지그 판 외곽 |
| `JIGOUT_02_PRODUCT` | 제품 윤곽 (참조용) |
| `JIGOUT_03_ESCAPE` | 피난홀 |
| `JIGOUT_04_GUIDE` | 가이드홀 |
| `JIGOUT_09_WARNING` | **검증 경고 — 반드시 확인** |
| `JIGOUT_10_NOTE` | 주기 |

`JIGOUT_09_WARNING` 에 표시가 있으면 최소 살두께를 위반한 곳입니다. 설계표준 값을 조정하거나
설계자가 직접 수정해야 합니다.

## 4. 실제 도면 없이 시험해보기

고객 도면을 쓰지 않고 동작을 확인할 수 있는 **합성 테스트 도면**을 만들 수 있습니다.

```bash
python make_test_fixture.py -o 테스트도면.dxf
python dxf_layer_classifier.py 테스트도면.dxf --png
python layout_engine.py 테스트도면_layered.dxf 설계표준시트.xlsx --png
```

만든 뒤에는 `지그도면_만들기.bat` 화면에서 이 도면을 골라도 됩니다.

이 도면은 **가상 데이터**이며 실제 제품이 아닙니다.
분류기를 일부러 어렵게 만드는 요소(라운드 코너, 미러 뷰, 극소 원 등)가 들어 있습니다.

## 5. 파일 구성

| 파일 | 역할 | 담당자가 고칠 일 |
|---|---|---|
| `make_rule_sheet.py` | 설계표준 시트 생성 | 항목을 늘리고 싶을 때 |
| `rules_loader.py` | 시트 읽기·검사 | **설계표준 항목 정의가 여기 있음** |
| `dxf_layer_classifier.py` | 제품도면 레이어 정리 | 회사 작도 습관에 맞게 조정 |
| `layout_engine.py` | 지그 배치·검증·출력 | 배치 방식을 바꾸고 싶을 때 |
| `web_app.py` | 웹 서버 (FastAPI) | API 를 늘리고 싶을 때 |
| `web_static/` | 웹 화면 (HTML/CSS/JS, 빌드 불필요) | 화면을 바꾸고 싶을 때 |
| `gui.py` | 담당자용 화면 | 보통 안 고침 |
| `*.bat` | 더블클릭 실행용 | 보통 안 고침 |
| `make_test_fixture.py` | 합성 테스트 도면 생성 | 보통 안 고침 |
| `test_*.py` | 회귀 테스트 | **고친 뒤 반드시 실행** |

> 코드를 고친 뒤에는 `python test_dxf_layer_classifier.py` 와
> `python test_rules_and_layout.py` 를 실행해 기존 동작이 깨지지 않았는지 확인하십시오.

## 6. 지금 못 하는 것 (알려진 한계)

| 항목 | 상태 |
|---|---|
| **3D 간섭 검증** | 없음. 2D 평면상 최소 살두께만 확인합니다 |
| **3D 모델 생성** | 없음. CAD 플랫폼 결정 후 별도 작업이 필요합니다 |
| 원이 아닌 홀(슬롯 등) | 외접 원으로 근사하고 알립니다. 설계자 확인 필요 |
| 여러 뷰가 있는 도면 | 가장 큰 뷰를 제품으로 쓰고 알립니다 |
| 풍선번호(원 없는 맨숫자) | 치수로 오분류될 수 있습니다 |
| 회사별 색상 규칙 | `--color-hint` 로 지정해야 합니다 (예: `--color-hint 1=CENTER`) |

### 실제 도면으로 아직 검증되지 않았습니다

지금까지의 시험은 **전부 합성 도면**으로 했습니다. 실제 고객 도면의 작도 습관
(색상 규칙, 표제란 구조, 블록 패턴)에서는 새로운 문제가 나올 가능성이 높습니다.

**실제 도면으로 처음 돌릴 때는 반드시 `_report.csv` 와 미리보기 PNG 를 눈으로 확인하십시오.**

## 7. 도움말

각 프로그램은 `--help` 로 사용법을 볼 수 있습니다.

```bash
python dxf_layer_classifier.py --help
python layout_engine.py --help
```

자주 쓰는 옵션:

| 옵션 | 뜻 |
|---|---|
| `--hole-max 30` | 이 크기 이하 폐곡선을 홀로 판정 (mm) |
| `--hole-min 1.5` | 이 크기 미만은 fiducial 로 보고 REVIEW 로 보냄 (mm) |
| `--color-hint 1=CENTER,8=HIDDEN` | 색상으로 선 용도를 구분하는 도면일 때 |
| `--png` | 미리보기 이미지 생성 |
